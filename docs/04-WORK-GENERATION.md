# Praxis Studio — Demo Work Generation
*The studio's real client work is under NDA. The website therefore launches with generated concept projects that prove the design language. Treat the generated set as the site's real portfolio — complete and final, not a stopgap. Generate them at portfolio quality — a visitor must feel "this is how it turned out, this is what they do, this is their design language."*

## The rule
**4 projects per service category — 16 total — each from a DIFFERENT subcategory** of that category, so every category shows its full range. Never fewer than 3 per category. Three concepts already exist and hold their slots (KOFFA, LEDGERLY, VELOUR); invent the other 13: names, scenario clients, industries, cities. Vary industries and scales — cafés to fintech, local to international. You have the final say on names and scenarios.

## The matrix
**Strategy & consulting** (subcategories: Audit and assessment / Communication strategy / Media plan / Brand platform)
1. Audit & assessment — a retail chain whose communication is audited end to end
2. Communication strategy — a public/NGO programme launch
3. Media plan — a tourism board's seasonal push
4. Brand platform — a fintech repositioning; the platform document is the deliverable

**Brand & creative** (Visual identity and logo / Brand guidelines / UX/UI design / Photo and video / Motion design / Print design)
1. Visual identity & logo — **KOFFA**, specialty coffee brand: *"How do you make a new coffee brand look like it has always existed?"*
2. Brand guidelines — a hotel group's complete guidelines system
3. UX/UI design — a banking app's interface system
4. Print design — a music festival's print suite (posters, passes, programme)

**Web & digital** (Websites and redesigns / E-commerce / Web and mobile apps / Intranet / AI-driven transformation)
1. Websites & redesigns — a clinic group's website redesign
2. E-commerce — a skincare brand's online store
3. Web & mobile apps — **LEDGERLY**, bookkeeping app: *"How do you make bookkeeping feel like a conversation?"*
4. AI-driven transformation — a hotel chain's AI booking/support assistant on its website

**Campaigns & media** (Media buying / Social ads and Google Ads / SEO / Social media / Reporting)
1. Social ads & Google Ads — an e-commerce campaign, with a headline metric
2. SEO — a local services company's search growth (SEO + AEO)
3. Social media — **VELOUR**, fashion label launch: *"How do you launch a label with no store and no ads?"*
4. Media buying — a retail opening across outdoor + radio + digital

## Every project page — the anatomy (Bitwip's template)
1. **Hero visual** — the strongest single image of the project.
2. **Headline = the client's QUESTION** ("How do you…?"). This is the format — every project leads with its question.
3. **Meta column:** CLIENT / INDUSTRY / SERVICES / LOCATION.
4. **CHALLENGE / SOLUTION / RESULTS** — short, concrete, written like a real case study, star-x bullets.
5. **One metric** where the type supports it (campaigns especially: Bitwip shows cards like "€20.4 in sales for every €1 spent"). Plausible, specific, never round-number bragging.
6. **Gallery:** 7–10 visuals in a dark staggered gallery — product shots, screens, packaging, campaign stills, scenario-based people where people belong. All generated by you, all in Praxis's design language (Bone/Inchworm/star-x world — never Bitwip's orange, never stock-photo generic).
7. **Prev / next project** navigation.
8. **Concept note** (small, on the Work index and each project page): concept projects — real client work is under NDA and replaces these as it clears.

## Where the projects appear
- **Home:** the work drag carousel features 5–6 of them (mix categories; include the metric-card style tile like Bitwip's).
- **Work index:** all 16, filterable by the 4 categories; each card shows category tag, the project name, and its question.
- **Service pages:** each service page features its own 4 projects.

## Image direction
Generate images as part of the build, per project, in a consistent art direction: warm Bone/cream backgrounds, black, Inchworm accents, pixel details where the brand calls for them. Screens (websites, apps) should look like real designed product shots, not grey wireframes. People, when used, are scenario-based (a barista for KOFFA, a shopkeeper for LEDGERLY) — natural, unstaged feeling. Nothing may look like a stock library pull.

## Editability
Build each project as a self-contained data block (name, question, meta, texts, metric, image set) so the founders can edit or replace any project later by changing one block — their choice, on their timeline. Say in your delivery notes how a block is edited.
